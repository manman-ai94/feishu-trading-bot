# 飞书交易助手 (Feishu Trading Assistant)

一个跑在 VPS 上的飞书机器人。它读取你的 OKX 账户，监控仓位，定时发简报，并在私聊和群里回答你的行情问题。回答问题时，AI 能查 OKX 上任意品种的实时行情，能联网搜新闻和经济数据，还能翻你喂给它的资料库。

装好以后它只读取，不下单。“经你确认后下单”的功能已经写在里面，但默认是关着的（`TRADING=off`），要你自己在服务器的 `.env` 里打开，而且建议先在模拟盘上把每种指令试一遍。打开以后，每一条指令都要你本人在私聊里回复确认码才会执行。代码里没有提币和划转的功能，打开下单以后也没有。详见下面的“下单”一节。

## 它现在能做什么

| 功能 | 你的私聊 | 群里 |
| --- | --- | --- |
| 开仓、加仓、减仓、平仓、止盈止损变动的提醒 | 有，含数量和盈亏 | 有，内容一样 |
| 风险提醒（保证金率偏低、离强平价近、当日亏损到线、持仓没挂止损） | 有 | 有 |
| 读不到 OKX 时的故障提醒 | 有 | 不发（只和你有关） |
| 盘前简报、收盘小结 | 有，结合你的持仓，带“今日英语” | 有，同一份 |
| 每周复盘 | 有 | 有，同一份 |
| 发“仓位”看持仓 | 完整账户信息 | 你 @机器人 发，同样是完整账户信息 |
| 问行情，例如“BTC 现在怎么看”“黄金今晚有什么数据” | 可以，AI 会结合你的持仓 | 你 @机器人 问，AI 同样会结合你的持仓 |
| 问题前加“深度”，多查几轮、分析得更细 | 可以 | 你可以 |
| 发“BTC 报价”，直接回 OKX 最新价（不经过 AI） | 可以 | 你可以 |
| 发“记住：……”往资料库里存内容，发“资料”查看 | 可以 | 你可以 |
| 发“用量”看 AI 花了多少钱 | 可以 | 你可以 |
| 发“登记本群”，把所在的群设为接收简报和提醒的群 | 不适用 | 你在群里 @机器人 发 |
| 发“重启”，让机器人重新读取配置 | 可以 | 不可以，只在私聊里 |
| 下单、平仓、撤单、设止盈止损（默认关闭，要先在 `.env` 里打开） | 可以，每条指令回复确认码才执行 | 你 @机器人 发，和私聊一样执行（`GROUP_TRADING=false` 可以关掉） |
| 发“算仓位 XAU 止损 3768”，按你定的单笔风险算最多开多大 | 可以 | 你可以 |

机器人只响应你本人的指令。群里其他人 @ 它，只会得到一句“我只响应主人的指令”。自动的提醒和简报照常发到群里，大家都看得到。

这两条规则在 `.env` 里可以改：

- `GROUP_SHOW_PNL=false`：群里不再显示资金和盈亏金额，只显示品种、方向和价位，AI 在群里也不再看你的账户，风险提醒和周复盘只发给你。
- `GROUP_OWNER_ONLY=false`：群里的其他人也可以 @机器人 问行情（每天有次数上限）。
- `GROUP_TRADING=false`：群里不执行下单类指令，只在私聊里执行。默认在登记的群里执行你本人发的指令；群里其他人发的下单指令和确认码一律不执行，不管这一项怎么设。`GROUP_SHOW_PNL=false` 时群里也不执行，因为预览里有持仓数字。

账户数据只会出现在你的私聊和你登记的那一个群里。机器人被拉进别的群，不会在那里显示任何账户信息。

AI 只做分析和提醒：给判断、精确的支撑位和阻力位，以及值得做计划的情景的触发价、目标价和失效价，不给“现在买入”这类指令，买卖由你自己决定。

回答没有固定的格式，跟着问题走：问一个事实就两三句话，追问只答追问的那一点，问自己的仓位就从开仓价和强平价讲起，要完整的判断时才展开。几句话的短回答是一条普通消息，长一些的才是卡片，卡片的标题由 AI 按内容起。你提问以后机器人不再回“正在查”，而是在你那条消息上点一个“正在输入”的表情，答完自动取消；只有等了超过 90 秒才补一句话（飞书不让点表情时是 30 秒，例如某些外部群）。打招呼和道谢只回一句话，发 `帮助` 才列出全部功能。下单指令不经过 AI：机器人按固定的写法读你的指令，AI 既看不到它，也不能替你发起它。

## AI 的装备

AI 回答问题和写简报时，可以自己决定调用下面这些工具，全部只读：

| 工具 | 作用 |
| --- | --- |
| OKX 行情 | OKX 上任意品种的最新价、24 小时区间、资金费率、持仓量，以及 15 分钟、1 小时、4 小时、日线的趋势和指标 |
| OKX K 线 | 取原始 K 线，用来找精确的波段高低点 |
| 联网搜索 | 查新闻、经济数据和公布时间、OKX 上没有的市场。回答末尾会列出引用的网页。搜索是一个问题里最花钱的部分，所以普通问题每次请求最多搜 3 次，“深度”问题最多 6 次 |
| 资料库 | 检索你存进去的交易规则、笔记和学习资料 |
| 群体持仓 | 别人怎么站队：OKX 大户的多空比（按账户数、按持仓量，现在和 24 小时前），黄金另有 CFTC 每周持仓报告里基金经理的多空和净持仓 |

模型和档位：默认用 Claude Opus 5.5 的中等档 (medium effort)，问题前加“深度”时用高档 (high)。在 `.env` 里用 `MODEL_DAILY`、`MODEL_DEEP`、`EFFORT_DAILY`、`EFFORT_DEEP` 调整。档位越高想得越细，也越慢越贵。

花费：每次 AI 工作用了多少都会记下来，发“用量”可以看今天和本月的估算金额（按公开价格算，实际以 Claude Console 的账单为准）。`AI_MONTHLY_BUDGET_USD` 是每月预算，默认 180 美元，到了以后机器人自动改用最省的档位，不会停止工作。

联网搜索需要在 Claude Console 里为你的组织开通 Web search。没开通的话机器人照常工作，只是查不了新闻，自检里会提示。不想用可以设 `WEB_SEARCH=false`。

资料库：就是服务器上的 `knowledge` 文件夹。你在飞书里发“记住：……”，内容会存进 `knowledge/notes.md`；整本的书或长文档，转成 `.md` 或 `.txt` 放进这个文件夹即可，不用重启。发“删除上一条”可以撤回刚存的笔记。你自己的笔记和文件只留在服务器上，不会上传到 GitHub。

`knowledge/library` 里是跟着代码一起发布的参考资料 (reference library)，根据公开来源整理，每条带出处，都是转述不是原话。现在有一份：段永平公开讲过的投资原则（不为清单、杠杆、做空、认错、看图看线、仓位、黄金、期权等 16 条）。来源网址在同一文件夹的 `_sources-duan-yongping.md` 里，这个文件机器人不检索。AI 引用这类资料时只拿来对照纪律和风险，不当作价位的依据。

群体持仓 (crowd positioning) 只当背景用：AI 可以拿它说明哪一边拥挤、追进去的风险多大，提示词里写明它不能当点位的依据，也不能单凭它判断方向，每个数字都带数据时间。两个来源都是公开数据，不用 key，不算联网搜索的次数：OKX 的大户多空比每小时更新；CFTC 的报告每周五公布，统计的是那个周二的持仓，读的是 `publicreporting.cftc.gov`，读不到时机器人照常工作，只是少这一段。每日简报的数据里也带这一段。不想用设 `CROWD_DATA=false`。

利率和美元 (rates and the dollar) 也只当背景：AI 用 `get_macro` 看美国 10 年期实际利率（TIPS）、10 年期国债收益率、10 年期盈亏平衡通胀率和美元广义指数，每个数字带日期和一周、一个月的变化。数据来自 FRED（圣路易斯联储）的公开 CSV，不用 key，不算联网搜索的次数，通常晚一两个交易日；一小时内重复问不会重复读，读不到时 30 分钟后再试，机器人照常工作。每日简报的数据里也带这一段。不想用设 `MACRO_DATA=false`。

同一个会话里两小时内的前五个来回，AI 会记得，所以可以追问“那 ETH 呢”。程序自己回的卡片（下单预览、已执行、当前持仓）也算在里面，确认码会被遮住，所以问“刚才改好了吗”“我要 @ 谁”时它知道刚发生了什么。

哪些消息交给 AI：只想看数字的短消息（“仓位”“看下持仓”）回持仓卡片，只问功能的（“你能做什么”）回帮助；只要问了判断、风险、是非或要不要做什么（“有没有必要平仓”“止损设了没有”），一律由 AI 结合账户回答。只是表个态（“好的”“我去跟 Claude 商量”）回一句话。

试回答效果：`python -m bot replay` 把 `scripts/replay-group.txt` 里群里问过的问题，按主人在群里 @机器人 的样子依次重放，只在命令行打印回答：不发飞书、不下单、不进成绩单，AI 调用照常计费（八个问题约一到两美元）。改了提示词以后用它对比前后。

## 你需要准备的东西

1. 一台专门跑机器人的 VPS（云服务器）。Windows 和 Ubuntu 都可以，下面两种都有步骤。只接 OKX 的话，Ubuntu 就够用，也更便宜。以后要接 MT5，需要 Windows。这台机器不要和别的用途共用，因为 OKX 的 key 会绑定它的 IP。机房地区要选你的 OKX 账户允许使用的地区。
2. GitHub 上的私有仓库 `feishu-trading-bot`（代码放这里）。
3. 飞书开放平台上的一个企业自建应用（下面有步骤）。
4. OKX 的 API key、Secret key 和 Passphrase（你已经有了）。
5. Claude 的 API key。

密钥和密码的规则只有一条：OKX、飞书、Claude 的密钥只填进 VPS 上的 `.env` 文件，服务器的登录密码只留在你自己手里。都不要发到任何聊天里（包括发给 Claude），不要截图，不要上传到 GitHub。

## 第一步：在飞书开放平台创建机器人

在电脑浏览器里打开 https://open.feishu.cn/app ，用你自己的飞书账号登录。菜单的名字以后可能略有变化，找意思相近的即可。

1. 点“创建企业自建应用”，名字可以叫“交易助手”。
2. 进入应用，在“添加应用能力”里添加“机器人”。
3. 在“凭证与基础信息”里能看到 App ID 和 App Secret。先不用复制，等会儿在 VPS 上填。
4. 在“权限管理”里，把下面四个权限逐个搜索出来并开通（直接把英文代码粘进搜索框）：
   - `im:message`
   - `im:message.p2p_msg:readonly`
   - `im:message.group_at_msg:readonly`
   - `im:message:send_as_bot`
5. “事件与回调”这一步先放着，等机器人在 VPS 上跑起来以后再回来做（见第四步的第 3 点）。

## 第二步：在 VPS 上安装

按你的系统选一种。

### Windows

用远程桌面登录 VPS，以下操作都在 VPS 上做。

1. 安装 Python 3.12：到 https://www.python.org/downloads/windows/ 下载 3.12 的 Windows installer (64-bit)。安装时务必勾选“Add python.exe to PATH”。我在 3.12 和 3.13 上测过，其他版本没有测。
2. 安装 Git：到 https://git-scm.com/download/win 下载安装，一路默认即可。
3. 打开“命令提示符”(Command Prompt)，依次输入下面两行。第二行里的 `你的用户名` 换成你的 GitHub 用户名。第一次会弹出 GitHub 的登录窗口，登录即可。

   ```
   cd C:\
   git clone https://github.com/你的用户名/feishu-trading-bot.git
   ```

4. 打开 `C:\feishu-trading-bot\scripts` 文件夹，双击 `setup.bat`。它会安装需要的组件，并生成一个空的 `.env` 文件。看到 `[OK] Setup finished` 就是成功了。

### Ubuntu

用 SSH 登录服务器（Ubuntu 24.04 自带 Python 3.12，不用另装）。

1. 刚登录时是 root 用户。输入下面三行，安装基础组件，并建一个专门跑机器人的普通用户 `bot`，然后切换到它：

   ```
   apt update && apt install -y python3-venv git gh
   adduser --disabled-password --gecos "" bot
   su - bot
   ```

2. 登录 GitHub 并下载代码。把 `你的用户名` 换成你的 GitHub 用户名：

   ```
   gh auth login
   gh repo clone 你的用户名/feishu-trading-bot
   cd feishu-trading-bot
   bash scripts/setup.sh
   ```

   `gh auth login` 会问几个问题，依次选 GitHub.com、HTTPS、Yes、Login with a web browser。它会显示一个一次性验证码，在你自己电脑的浏览器里打开 https://github.com/login/device ，输入验证码即可。看到 `[OK] Setup finished` 就是安装成功了。

## 第三步：填写 .env

- Windows：用记事本打开 `C:\feishu-trading-bot\.env`。
- Ubuntu：在 `feishu-trading-bot` 文件夹里输入 `nano .env`。改完按 Ctrl+O 再按回车保存，按 Ctrl+X 退出。

在等号后面填值，等号两边不要加空格和引号。这一轮先填这些：

- `FEISHU_APP_ID` 和 `FEISHU_APP_SECRET`：飞书应用的“凭证与基础信息”页面。
- `OKX_API_KEY`、`OKX_SECRET_KEY`、`OKX_PASSPHRASE`：你现有的那把 OKX key。
- `ANTHROPIC_API_KEY`：Claude 的 API key。

`OWNER_OPEN_ID` 先空着，第四步会拿到。`GROUP_CHAT_ID` 不用手填，第四步在群里发一句“登记本群”就行。其余的项都有默认值，文件里每一项上面都有中文说明。

不想在服务器上开记事本的话，也可以把 `名字=值` 一行一个地从标准输入送给 `python -m bot setenv`，它会把值写进 `.env`，屏幕上只显示写了哪几个名字，不显示值。比如从自己的电脑通过 SSH 送过去，密钥就不用经过远程桌面的剪贴板。值留空的行表示这一项不改。

密钥是一项一项手工粘贴的，容易贴错行。`python -m bot checkenv` 会按格式判断每个密钥是不是填在了对的位置，只显示名字，不显示值。填错位置的密钥机器人一律当作没填，不会把它发给不相干的服务。`python -m bot clearenv 名字 名字` 可以把指定的几项清空。

## 第四步：自检、启动、登记

1. 自检 (self-check)。它会逐项检查配置、OKX、Claude 和飞书，`[OK]` 是通过，`[X]` 是没通过并附原因，`[!]` 是提醒。这一轮出现“还没填 OWNER_OPEN_ID”的提醒是正常的。如果飞书这一项暂时没通过，先接着做下面几步，等应用发布以后再自检一次。
   - Windows：双击 `scripts\selfcheck.bat`。
   - Ubuntu：输入 `.venv/bin/python -m bot selfcheck`。
2. 启动机器人。
   - Windows：双击 `scripts\start.bat`。这个黑色窗口要一直开着。
   - Ubuntu：先输入 `exit` 回到 root 用户，再输入下面这一行。它把机器人装成系统服务，在后台运行，掉线会自动重启，服务器重启后也会自己启动。

     ```
     bash /home/bot/feishu-trading-bot/scripts/install-service.sh
     ```

3. 回到飞书开放平台，做“事件与回调”的配置：
   - 订阅方式选“使用长连接接收事件”并保存。如果提示应用还没有建立长连接，说明机器人没在运行，回到上一步确认它已经启动。
   - 点“添加事件”，搜索 `im.message.receive_v1`（接收消息）并添加。
4. 在“版本管理与发布”里创建一个版本并发布。可用范围要包含你自己。发布之后权限和事件才生效。
5. 在飞书里搜索你的机器人，私聊它发送 `/whoami`。它会回你的 open_id，把它填进 `.env` 的 `OWNER_OPEN_ID`。
6. 重启机器人，让 `OWNER_OPEN_ID` 生效。你会在私聊里收到“交易助手已上线”的卡片，里面有当前的账户和持仓。
   - Windows：关掉黑色窗口，重新双击 `scripts\start.bat`。
   - Ubuntu：以 root 用户输入 `systemctl restart feishu-trading-bot`。
   - 以后改了 `.env`，在私聊里给机器人发“重启”就可以，不用登录服务器。
7. 建一个群，把朋友拉进来，再在群设置的“群机器人”里添加你的机器人。在群里 @机器人 发送“登记本群”。它会把这个群记下来，以后简报和提醒都发到这里，不用重启。

关于朋友：朋友是你飞书组织（团队）的成员时，直接拉进群即可。朋友在组织外面时，要先在开放平台“版本管理与发布”里打开“允许机器人被添加到外部群中使用”并发一个新版本。这个开关要求你先完成个人实名认证或企业认证，认证入口就在开关旁边。

## 第五步：把 OKX 的 key 绑定到 VPS 的 IP

在 OKX 的 API 管理页面编辑这把 key，把“绑定 IP 地址”填成 VPS 的公网 IP（在 VPS 服务商的控制台里能看到）。这样即使 key 泄露，别的机器也用不了。另外，OKX 官方说明里写着，带交易权限但没有绑定 IP 的 key，闲置 14 天会被自动删除。

提币权限保持关闭。只想让机器人监控的话，这把 key 只勾“读取”就够了；要用下面的下单功能，才需要再勾上“交易”。自检会显示这把 key 实际有哪些权限。

## 日常使用

- 发“仓位”：看账户和持仓。私聊里直接发，群里要 @机器人。
- 直接提问：例如“BTC 现在怎么看”“黄金今晚有什么数据”。OKX 上有的品种都能问。
- 在问题前加“深度”：例如“深度 下周黄金怎么看”，AI 会多查几轮、分析得更细，也更慢更贵。
- 发“BTC 报价”或“黄金多少钱”：直接回 OKX 的最新价，不经过 AI，几秒就回。
- 发“记住：……”：把交易规则、心得或资料存进资料库。发“资料”看里面有什么，发“删除上一条”撤回。
- 发“用量”：看今天和本月 AI 大约花了多少钱。
- 发“成绩单”：看 AI 给过的点位事后对了多少，规则见下面“成绩单”一节。
- 在群里 @机器人 发“登记本群”：把这个群设为接收简报和提醒的群。
- 私聊发“重启”：机器人重新启动并读取 `.env`，大约半分钟回来。
- 发“帮助”：看说明。
- 发 `/whoami`：看自己的 open_id 和当前会话的 chat_id。

定时简报的时间、提醒线、群里的规则、模型和档位，都在 `.env` 里改。改完私聊给机器人发“重启”。

持仓没挂止损的提醒：一个仓位连续 10 分钟（`ALERT_NO_STOP_MINUTES`）没有止损单，机器人提醒一次，写明数量、均价、浮动盈亏和离强平价多远；之后只要还没挂，每 24 小时再提醒一次，挂上就停，重启不会重复提醒。只有止盈没有止损也算没挂。设不设、设在哪由你决定，机器人不替你定价位。某一次读不到 OKX 的止损单时，机器人不会把它当成“止损没了”，沿用上一次看到的。实盘下单开着的时候，提醒的最后一行写好现成的指令（例如“止损 XAU 价格”），价格由你填。

### 提醒有多快

机器人每 30 秒读一次账户（`POLL_SECONDS`）。另外它连着 OKX 的私有推送 (private WebSocket)，订阅了仓位、止盈止损单和强平预警三个频道：止损被打、仓位变了、OKX 发出强平预警时，推送一到机器人就马上读一次账户，提醒通常几秒内就到飞书。推送只负责“叫醒”，提醒的内容仍以随后从 OKX 读到的数字为准；推送断了会自动重连，期间照常每 30 秒读一次。推送只读，订阅的频道都不能下单。不想用设 `OKX_STREAM=false`。

### 风险读数（只读，不动仓位）

持仓卡片、简报和 AI 看到的账户里，每个仓位多几行程序算好的数：

- 实际杠杆：全部仓位的名义价值 ÷ 账户权益。它和你在 OKX 上设的杠杆倍数不是一回事，后者只决定占用多少保证金。
- 强平距离：标记价离预估强平价多远，再折合成几天的正常波幅（日线 ATR，取全部日子和只算工作日两种算法里大的那个）。
- 止损触发时少多少钱、占权益百分之几；没有止损时，价格走到强平价要亏多少。
- 资金费：这一期的费率，按现在的仓位每期和每天大约付或收多少。

这些读数越过提醒线时，发一张“仓位风险提醒/警告/紧急”卡片，只在变严重时发，同一张卡至少隔半小时，重启不重复。默认的线：

| 设置 | 默认 | 含义 |
| --- | --- | --- |
| `RISK_PER_TRADE_PCT` | 1 | 你定的单笔风险：一笔交易止损触发时最多亏权益的百分之几。“算仓位”按它算 |
| `ALERT_STOP_RISK_PCT` | 跟 `RISK_PER_TRADE_PCT` 一样 | 已挂的止损触发时亏得比这个多，就提醒 |
| `ALERT_LIQ_ATR` | 3,2,1 | 强平距离不到 3、2、1 天的正常波幅，分别是提醒、警告、紧急 |
| `ALERT_LEVERAGE` | off | 实际杠杆超过几倍提醒，例如 `5,10`。默认不提醒，因为你的做法是 OKX 上固定 100 倍、用仓位大小控制风险 |
| `WEEKEND_CHECK` | true | 每周五 21:00 UTC（黄金周末休市前一小时）检查一次：没有止损、止损太近、离强平太近，有就发一张“周末前检查” |
| `WEEKEND_LEVERAGE` | off | 周末前实际杠杆超过几倍就写进检查 |
| `WEEKEND_STOP_ATR` | 1.5 | 周末前止损离标记价不到几天的正常波幅，就写进检查 |

每张卡片都只写读数和你设的线，最后一句是“由你决定”。机器人不会自己减仓或挪止损；要动手，发指令，回确认码才执行。

### 算仓位

发“算仓位 XAU 止损 3768”（按现价）或“算仓位 XAU 入场 3873 止损 3768”。机器人按 `RISK_PER_TRADE_PCT` 算：这一笔最多亏多少钱、最多开几张、名义价值和实际杠杆、按你现在的杠杆设置占多少保证金，以及你现在的仓位按同样的止损距离要亏多少。只算数，不下单，下单功能关着也能用。

## 下单（默认关闭）

### 怎么打开

在服务器的 `.env` 里改 `TRADING`，然后重启机器人。这一项和所有限额只能在 `.env` 里改，飞书里发什么都改不了。

- `TRADING=off`（默认）：只读取。发下单指令，机器人会回“下单功能是关着的”。
- `TRADING=demo`：在 OKX 模拟盘 (demo trading) 下单。需要在 OKX 的“模拟交易”里单独建一把 key，填进 `OKX_DEMO_API_KEY`、`OKX_DEMO_SECRET_KEY`、`OKX_DEMO_PASSPHRASE`。这时仓位监控和简报看的仍然是实盘账户，下单、预览和各项检查用的是模拟账户，两边互不影响。
- `TRADING=live`：在实盘下单，用的是 `OKX_API_KEY` 那一把，它要有“交易”权限。

建议的顺序：先 `demo`，在私聊里发 `模拟盘自测` 让机器人自己把每种指令跑一遍（见下面“模拟盘自测”），也可以自己再试几条，看预览和回报是不是你想的那样，再决定要不要 `live`。

实盘可以一步一步放开。`.env` 里的 `TRADE_ACTIONS` 写明开放哪几类操作，没写的机器人直接拒绝，不出预览，也不会发到 OKX：

| 写法 | 开放的操作 |
| --- | --- |
| `stops` | 给已有仓位设置、修改、取消止盈止损 |
| `close` | 平仓、减仓、全部平仓 |
| `cancel` | 撤单 |
| `limit` | 限价挂单开仓 |
| `open` | 市价开仓、加仓 |

例如第一步 `TRADE_ACTIONS=stops`，用顺了改成 `stops,close,cancel`，最后 `all`。默认是 `all`。写错的词不会开放任何东西，自检和启动日志会指出来。看挂单、看交易设置不受它限制。发“交易设置”能看到现在开放了哪几类。

OKX 账户的“账户模式”要是“合约模式”（以前叫“现货和合约模式”），或者进阶模式里的跨币种、组合保证金。新建的模拟账户常常是“现货模式”，这个模式下 OKX 不接受合约订单（错误码 51010），机器人会在预览之前直接说明。改的地方：OKX 网页或 App 里进合约的交易页，点右上角的“···”，进“交易设置”里的“交易模式”，第一次只能在那里改。发“交易设置”可以看到当前的账户模式和下单账户里的资金。

### 模拟盘自测 (demo self-test)

下单的每条规则都有自动测试，但测试用的是假的交易所。OKX 本身收不收机器人发的每一种请求，要真发一次才知道。`TRADING=demo` 时在私聊里发 `模拟盘自测`，机器人回一张预览，你回一次确认码，它就在模拟账户上用合约允许的最小数量的两倍（黄金大约是 0.002 盎司、8 USDT 名义价值，准确数字写在预览卡片上）依次做八件事：

1. 市价开多
2. 给仓位挂止损和止盈
3. 改止损
4. 减掉一半（止盈止损应该还在）
5. 取消止盈（先撤掉原来那张，再挂一张只有止损的）
6. 在现价下方 3% 挂一张限价买单
7. 撤掉它
8. 平仓（OKX 应该把止损单一并撤掉）

每一步都走和你下单时同一套检查和同一条发单路径，发出去以后机器人到 OKX 把仓位、挂单和止盈止损单读回来核对，对了才做下一步。哪一步 OKX 拒绝了，或者收了但读回来的结果不对，它就停下，把已经开的仓位和挂单收掉，回一张卡片写明停在第几步、OKX 的原话和错误码，以及账户里还有没有留下东西。全部通过大约要半分钟，这期间你的消息上会有一个“正在输入”的表情。

- 只在模拟盘跑。`TRADING=live` 时它直接拒绝，预览时查一次，确认时再查一次。
- 默认用允许下单的品种里的第一个，也可以点名：`模拟盘自测 BTC`。
- 这个品种在模拟账户上要是空的（没有仓位、挂单、止盈止损单），否则它不动，免得碰到你自己试的单子。
- 要求五类操作都开放（`TRADE_ACTIONS=all`），会用掉当天 2 次开仓次数。
- 最近一次的结果（时间、版本、通过还是停在哪一步）记在数据库里，发“交易设置”或在服务器上运行 `python -m bot trading` 都能看到。换了版本以后，它会提示这个版本还没有跑过。
- 自测通过说明下单的通道是通的，和行情判断无关。实盘发的是同样的请求，成交价和滑点会和模拟盘不同。

### 一张单是怎么下出去的

1. 你在私聊里（或在登记的群里 @机器人）发指令，例如 `做多 XAU 100张 止损 3860`。
2. 机器人算出实际会发给 OKX 的内容，对照限额检查一遍，回一张预览卡片：品种、方向、数量（张数和合多少币）、名义价值、杠杆和大约占用的保证金、止损止盈离现价多远，触发时账户比现在少或多多少、从开仓均价算这笔交易是多少，再加一个四位确认码。卡片标题写着“模拟盘”还是“实盘”。
3. 你回复确认码：`确认 1234`、`1234`、`确认1234执行` 都行，只要这句话短、里面有这四位数。机器人用最新的价格和仓位把所有检查重做一遍，通过了才发单，然后告诉你成交了多少、均价多少、订单号是什么。

不是固定写法也可以。“把我的止损减两点”“3808 的止损挪到 3806”这类话，程序自己认不全时，交给 AI（快速档）按你现在的持仓改写成一条固定写法的指令，例如 `止损 XAU 3806`。改写出来的指令照样走上面三步：预览第一行写明“我把……理解为……”，你回确认码才执行。AI 只负责改写，不能替你确认、取消或改设置；它看不懂的话，不会出预览，按问题回答。每次改写要调一次快速模型，花费很小，记在“用量”里。

确认码只能用一次，120 秒过期，只对它所在的那张预览有效。回复 `取消` 作废。发了新指令，旧的预览自动作废。价格在你确认前动了超过 0.5%，或者这个品种的仓位变了，都要重新发指令。

### 指令

| 你发 | 意思 |
| --- | --- |
| `做多 XAU 100张`、`做空 BTC 0.01个`、`做多 XAU 500U` | 市价开仓。`张` 是合约张数，`个` 是币的数量（黄金就是盎司），`U` 是仓位的名义价值，不是保证金 |
| `限价做多 XAU 100张 3850`、`挂单做空 BTC 0.01个 68000` | 限价挂单 |
| 在开仓指令后面加 `止损 3860 止盈 3950` | 随单带止损止盈，成交后生效，触发时按市价平 |
| `加仓 XAU 100张` | 按现有仓位的方向再开 |
| `平仓 XAU`、`平仓 XAU 一半`、`平仓 XAU 30%`、`减仓 XAU 100张` | 市价平掉全部或一部分，只减仓，不会反手 |
| `全部平仓` | 市价平掉所有允许下单的品种上的仓位 |
| `挂单` | 看当前的挂单和止盈止损 |
| `撤单 XAU`、`撤单 全部`、`撤单 订单号` | 撤掉没成交的挂单 |
| `止损 XAU 3860`、`止盈 XAU 3950`、`止损 XAU 3860 止盈 3950` | 给整个仓位设或改止盈止损 |
| `取消止损 XAU`、`取消止盈 XAU`、`取消止盈止损 XAU` | 撤掉止盈止损 |
| `停止交易` / `恢复交易` | 总开关：停了以后不再接受开仓，平仓、撤单、改止损照常 |
| `交易设置` | 看现在是模拟盘还是实盘、各项限额、这把 key 的权限、最近一次自测的结果 |
| `模拟盘自测`、`模拟盘自测 BTC` | 只在模拟盘：机器人自己把每种指令跑一遍，见上面“模拟盘自测” |
| `交易帮助` | 看这张表 |

数量必须带单位。写得不完整或者有歧义的指令（例如 `做多 XAU 100`、`卖出 XAU 100张`），机器人会说哪里没看懂，不会猜。带问号或“怎么样”“要不要”的句子不算指令，照常交给 AI 回答。

### 限额（都在 .env 里）

| 配置项 | 默认 | 作用 |
| --- | --- | --- |
| `TRADE_INSTRUMENTS` | 和 `WATCH_INSTRUMENTS` 一样 | 只有名单里的品种能下单、平仓、撤单。只支持 USDT 或 USDC 本位的永续合约 |
| `TRADE_MAX_ORDER_USD` | 1000 | 单笔上限，按名义价值算 |
| `TRADE_MAX_POSITION_USD` | 3000 | 单个品种的持仓上限，已有仓位和没成交的挂单都算在内 |
| `TRADE_MAX_OPENS_PER_DAY` | 20 | 每天最多开仓几次 |
| `TRADE_DAILY_LOSS_LIMIT_USD` | 不设 | 当天权益少了这么多以后不再开新仓（只管实盘） |
| `TRADE_MAX_DEVIATION_PCT` | 1.0 | 限价往“会立刻成交”的方向最多偏离现价百分之几 |
| `TRADE_MAX_DRIFT_PCT` | 0.5 | 从预览到确认，价格最多可以动百分之几 |
| `TRADE_MARGIN_MODE` | cross | 新仓位用全仓还是逐仓 |
| `TRADE_CONFIRM_SECONDS` | 120 | 确认码的有效时间 |
| `TRADE_REQUIRE_STOP` | false | 设成 true 以后，开仓不带止损就不执行 |
| `TRADE_ACTIONS` | all | 开放哪几类操作，见上面“怎么打开” |

限额只拦开仓。平仓、撤单、改止损不受限额影响，因为它们只会减小风险。

### 它不做的事

- 不改杠杆倍数。预览里显示的是你在 OKX 里设好的倍数。
- 不做现货和币本位合约，不做提币和划转。
- 不会自己发起任何一张单，也不会在连接断掉以后自动重发。连接在发单途中断了，它会去 OKX 查这张单到没到，查不清就明说“结果不确定”，请你自己核对。
- 群里只执行你本人在登记过的群里 @机器人 发的指令（`GROUP_TRADING`，默认开）。别人发的指令和确认码都不执行。预览和确认码会显示在群里，群里的人都看得到。

每一次发给 OKX 的指令和结果都记在 `data/bot.db` 的 `orders` 表里。`python -m bot trading` 可以在服务器上打印当前的下单设置和 key 的权限，只读取，不花钱。

### 还没在真实的 OKX 上验证过的地方

下单功能的每条规则都有自动测试，但测试用的是假的交易所。所以开实盘之前先在模拟盘发一次 `模拟盘自测`：它把给整个仓位设止盈止损、修改止盈止损、减仓、平仓时附带撤掉止盈止损这几种最容易出问题的请求都真发一遍。如果 OKX 拒绝了某一种，卡片里有 OKX 的原话和错误码，把它发给维护的人就能定位。自测没有覆盖的：做空、双向持仓账户、逐仓、“全部平仓”一次平多个品种、连接中断后的查单。

## 成绩单 (track record)

AI 每次给出某个品种的多空情景时，机器人把里面的触发位、目标位、失效位和结论的方向记下来，之后自动对照 OKX 的 15 分钟 K 线打分。打分是程序按固定规则做的，不经过 AI，也不多花 AI 的钱。私聊发 `成绩单` 查看，也可以写 `成绩单 XAU`、`成绩单 90天`。

规则：

- 15 分钟 K 线收盘站上触发位（空头情景是跌破）才算触发。只是影线碰到不算。
- 触发以后，先碰到目标位算命中，先碰到失效位算失效。同一根 K 线里两个都碰到，按失效算，因为分不清先后。
- 72 小时（`TRACK_WINDOW_HOURS`）内两个都没到，算到期，按到期时的价格计。一直没触发的情景不计入命中率。
- 盈亏用 R 表示：把“触发位到失效位的距离”当作 1R。失效是 -1R，命中是目标位离触发位有几个 R。
- 方向判断（偏多、偏空）和 24 小时、72 小时后的价格比，旁边列出同样这些样本里价格上涨的比例，也就是“一直看多”能得到的数，作为对照。

它核对的是分析的点位和事后的行情，不是交易记录，也不代表收益：有没有人照着这些点位交易，这里不知道。有结果的情景不到 20 个时，比例说明不了什么。机器人停机超过三天，中间到期的情景会标成“没法评”，不会靠猜补上。

`TRACK_RECORD=false` 可以关掉。`python -m bot record` 在服务器上打印同一张成绩单，只读取记录。

## 心跳和备份 (heartbeat and backup)

- 停机会被说出来。机器人每分钟记一次时间。再次启动时如果发现中间空了 5 分钟以上，上线卡片的第一行会写明停了多久、从几点到几点，因为那段时间没有监控仓位。
- 整台服务器停掉时，机器人自己发不出消息。想在这种时候也收到通知，可以用 healthchecks.io 这类“超时没来就报警”的服务：在那边建一个检查，把它给的网址填进 `HEARTBEAT_URL`，机器人每 5 分钟访问一次，访问时不带任何账户信息。不填就不访问。
- 每天自动备份。仓位记录、事件、订单、成绩单（`data/bot.db`）和你发给机器人的笔记，每天复制一份到 `data/backups/`，默认保留 14 天（`BACKUP_KEEP_DAYS`，填 0 关掉）。恢复的办法：停掉机器人，把 `data/backups/bot-日期.db` 复制成 `data/bot.db`，再启动。备份和数据在同一台服务器上，服务器硬盘坏了会一起丢，重要的话定期把 `data/backups` 下载到别处。

## 让它一直运行

### Windows

平时：`start.bat` 的窗口开着就行。断开远程桌面时直接关掉远程桌面的窗口，不要选“注销”(sign out)，否则机器人会跟着停。机器人如果意外退出，窗口会在 15 秒后自动重新启动它。

VPS 重启后自动启动（可选）：以管理员身份打开命令提示符，输入下面这一行。之后 VPS 每次开机都会在后台启动机器人，没有窗口，运行情况看 `logs\bot.log`。

```
schtasks /Create /TN "FeishuTradingBot" /TR "C:\feishu-trading-bot\scripts\start.bat" /SC ONSTART /RU SYSTEM /F
```

用了开机自启以后，就不要再手动双击 `start.bat`，否则会有两个机器人同时回话。取消自启的命令是 `schtasks /Delete /TN "FeishuTradingBot" /F`。

### Ubuntu

第四步里的 `install-service.sh` 已经把它装成了系统服务，不需要再做什么。常用命令（以 root 用户）：

```
systemctl status feishu-trading-bot     看它是否在运行
systemctl restart feishu-trading-bot    重启（改了 .env 之后要做）
systemctl stop feishu-trading-bot       停止
tail -n 50 /home/bot/feishu-trading-bot/logs/bot.log    看最近的运行记录
```

### 哪些部分我实测过

Ubuntu 的 `setup.sh` 我在 Linux 上实际跑通过，生成的服务文件也通过了 systemd 的格式检查。没有实测的部分：服务在真实服务器上的启动、`gh` 登录这一步，以及 Windows 的 `.bat` 脚本和 schtasks 命令（我没有 Windows 机器）。第一次用的时候如果报错，把报错文字发我，注意别带上密钥。

## 更新

- Windows：双击 `scripts\update.bat`，然后关掉机器人窗口，重新双击 `start.bat`。
- Ubuntu：以 `bot` 用户在项目文件夹里输入 `bash scripts/update.sh`，再以 root 用户输入 `systemctl restart feishu-trading-bot`。

## 常见问题

- 自检里 OKX 行情读取失败：这台机器连不上 OKX。先确认机房地区是你的 OKX 账户允许使用的地区。
- 自检里 OKX 账户读取失败：多半是 key 填错、Passphrase 不对，或者这把 key 绑定的 IP 不是这台 VPS。
- 自检里提示时间相差好几秒：打开系统的自动校时。
- 自检里提示联网搜索用不了：到 Claude Console 的组织设置里开通 Web search，再私聊机器人发“重启”。
- AI 回答太慢或太贵：把 `EFFORT_DAILY` 调低一档（例如 low），或者把 `MODEL_DAILY` 换成 `claude-sonnet-5-5`。
- 飞书里发消息没反应：检查应用是否已发布、事件 `im.message.receive_v1` 是否已添加、四个权限是否都开通。群里要 @机器人 才会回答，而且默认只回答你本人。
- Windows 的黑色窗口里中文显示成方块：不影响运行。可以在窗口标题栏上点右键，属性，字体，换成“新宋体”(NSimSun)。
- 想看运行记录：`logs` 文件夹里的 `bot.log`。交易记录和账户快照在 `data` 文件夹里的 `bot.db`。

## 代码结构（给以后维护的人看）

```
bot/config.py         读取 .env，检查配置
bot/okx_client.py     OKX 只读客户端（签名、行情、账户、持仓、止盈止损、查挂单）
bot/okx_stream.py     OKX 私有推送：仓位、止损单或强平预警一变就叫监控马上读一次（只读，不下单）
bot/okx_trade.py      会改动东西的 OKX 调用：下单、撤单、平仓、止盈止损。只有打开下单功能时才创建
bot/trading.py        下单流程：读指令、对照限额检查、预览、确认码、执行、回报
bot/selftest.py       模拟盘自测：用最小数量把每种指令在 OKX 模拟盘上真发一遍并核对
bot/risk.py           风险读数：实际杠杆、强平距离折合几天波幅、止损代价、资金费，以及提醒线
bot/track.py          成绩单：从 AI 的回答里取出点位，按 K 线打分，出成绩单卡片
bot/upkeep.py         心跳（发现停机）和每天的数据备份
bot/models.py         数据结构
bot/indicators.py     EMA、RSI、ATR
bot/instruments.py    把“BTC”“比特币”这样的说法对应到 OKX 的品种
bot/market.py         把行情整理成给 AI 看的事实清单，以及不经过 AI 的报价
bot/knowledge.py      资料库：存笔记、检索 knowledge 文件夹里的文档
bot/tools.py          AI 可以调用的工具：行情、K 线、资料库、群体持仓、利率和美元、联网搜索
bot/crowd.py          群体持仓：OKX 大户多空比、CFTC 持仓周报（只作背景）
bot/macro.py          利率和美元：FRED 的实际利率、国债收益率、通胀预期、美元指数（只作背景）
bot/monitor.py        仓位变化检测和风险规则（纯规则，不用 AI）
bot/journal.py        SQLite 交易日志、账户快照、AI 用量和下单记录
bot/analyst.py        调用 Claude：给消息分类、带工具的问答和简报、用量统计和预算
bot/reports.py        文字排版，含金额的完整版和只有价位的简版
bot/service.py        决定什么发给你、什么发到群
bot/router.py         处理收到的消息，执行“只认主人”和账户可见范围的规则
bot/scheduler.py      定时任务
bot/feishu_client.py  飞书收发消息（长连接）
bot/app.py            把各部分接起来
bot/__main__.py       命令行入口：run、selfcheck、status、brief、quote、setenv、checkenv、clearenv、trading、replay
knowledge/            资料库文件夹（内容不进 GitHub）
scripts/              Windows 的 .bat 和 Linux 的 .sh 安装、启动、更新脚本
tests/                自动测试，运行方式：python -m pytest
```

开发时安装测试依赖：`pip install -r requirements-dev.txt`。
